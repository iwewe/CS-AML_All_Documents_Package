# CS-AML Technology Architecture v0.1

**Status:** Normative derivative specification

**Architecture stance:** Implementation-neutral normative core; reference technology profiles are non-normative.

## Architectural axiom
Technology SHALL preserve analytical uncertainty rather than erase it. Direct evidence, reconstructed value flow, inference, hypothesis, and assessment MUST remain distinguishable in storage, API responses, search, visualisation, automation, and exported intelligence products.

## Core logical architecture
```text
USER EXPERIENCE
  -> API / POLICY ENFORCEMENT
  -> APPLICATION SERVICES
  -> SEARCH / GRAPH / WORKFLOW
  -> CANONICAL DATA + EVIDENCE + AUDIT
  -> IAM / KMS / OBSERVABILITY / BACKUP
```

## Key normative rules
- Canonical records SHALL be distinguishable from rebuildable projections.
- Original evidence SHALL be preserved separately from derivatives.
- Entity merges SHALL be reviewable and reversible.
- Search, graph, and AI outputs SHALL remain attributable to canonical objects.
- Direct, documented, reconstructed, and hypothetical value flows SHALL remain distinct.
- High-impact dissemination SHALL require human authorization and generate audit evidence.
- AI SHALL NOT autonomously determine guilt, approve dissemination, or silently convert suggestion into fact.
