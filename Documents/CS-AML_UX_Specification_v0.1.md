# CS-AML UX Specification v0.1

**Status:** Normative UX baseline for MVP 0.1

## UX axiom
The interface SHALL preserve analytical uncertainty rather than visually collapse it. Facts, claims, inferences, candidate matches, hypotheses, reconstructed value flows, and final assessments remain perceptibly different throughout the user journey.

## Scope boundary
This document defines interaction behaviour, task flows, states, feedback, safety, accessibility, provenance semantics, and usability requirements. It intentionally does **not** define final sitemap, taxonomy, navigation architecture, object hierarchy, route taxonomy, or global findability. Those belong to the separate **CS-AML Information Architecture Specification**.

## UX goals
- Traceable
- Uncertainty-aware
- Reversible
- Safe-by-default
- Efficient
- Reviewable
- Accessible
- Calm

## Critical UX domains
1. Case and workflow
2. Source/evidence/document handling
3. Entity resolution
4. Relationship/ownership/assets
5. Timeline
6. Follow-the-value
7. Typology/indicator analysis
8. Hypothesis and assessment
9. Search and investigation graph
10. Peer review
11. Dissemination/export
12. Protected-source and permission handling
13. Accessibility
14. AI-assisted UX guardrails
15. Usability testing

## Mandatory value-flow visual classes
`DIRECT | DOCUMENTED | RECONSTRUCTED | HYPOTHETICAL`

## UX-IA separation
UX owns interaction behaviour. IA owns organisation and findability. Joint decisions include user-facing labels, task entry points, deep-link/context preservation, and terminology consistency.

## UX Definition of Done
A feature is UX-complete only when critical states, accessibility, provenance/uncertainty semantics, high-impact action safety, and relevant usability verification are complete.
